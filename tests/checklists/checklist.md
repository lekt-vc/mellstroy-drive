# Комплексный чек-лист тестирования «MELLDRIVE»
**Команда:** MellSquad

---

## 1. Чек-лист соответствия макету (UI / Pixel-Perfect)
- [ ] 1.1. Цвета и градиенты соответствуют утвержденному UI-киту (основной цвет, акцентные кнопки, статус бейджей).
- [ ] 1.2. Типографика: семейство шрифтов, размеры h1–h6, интервалы и начертания соответствуют Figma.
- [ ] 1.3. Отступы (padding, margin) между карточками авто и секциями кратны принятой сетке (8px).
- [ ] 1.4. Иконки (КПП, топливо, класс авто) отображаются в векторе (SVG), не размыты.
- [ ] 1.5. Реализованы все состояния интерактивных элементов: `:hover`, `:focus-visible`, `:active`, `:disabled`.
- [ ] 1.6. Активный пункт в шапке/навигации подсвечен.
- [ ] 1.7. На всех кликабельных элементах курсор переключается на `pointer`.
- [ ] 1.8. Фавиконка сервиса отображается во вкладке браузера.

## 2. Чек-лист адаптивности и кроссбраузерности
- [ ] 2.1. Ширина 320 px — отсутствие горизонтальной полосы прокрутки, контент доступен.
- [ ] 2.2. Ширина 375 px (смартфоны) — компактная сетка авто, удобный тап по кнопкам.
- [ ] 2.3. Ширина 768 px (планшеты) — адаптация меню и формы бронирования.
- [ ] 2.4. Ширина 1024 px (ноутбуки) — корректный перенос фильтров.
- [ ] 2.5. Ширина 1440 px и 1920 px (десктоп) — ограничение максимальной ширины контейнера (`container`).
- [ ] 2.6. Мобильное бургер-меню плавно открывается и закрывается при клике вне области или по крестику.
- [ ] 2.7. Проверено в Google Chrome, Mozilla Firefox, Microsoft Edge, Яндекс.Браузере.
- [ ] 2.8. Проверено на реальном мобильном устройстве (iOS / Android).

## 3. Чек-лист функциональности каршеринга
- [ ] 3.1. Каталог автомобилей: работают фильтры по классу (Эконом, Комфорт, Бизнес, Электро).
- [ ] 3.2. Сортировка по стоимости аренды (от дешевых к дорогим и наоборот).
- [ ] 3.3. Карточка автомобиля: отображение характеристик (год, КПП, двигатель, доступность).
- [ ] 3.4. Выбор тарифа (минуты / часы / сутки) с автоматическим пересчетом итоговой стоимости.
- [ ] 3.5. Бронирование: проверка занятости автомобиля на выбранные даты/время.
- [ ] 3.6. Личный кабинет: отображение статуса текущей аренды и истории завершенных поездок.
- [ ] 3.7. Админ-панель: создание, редактирование и удаление автопарка (CRUD).
- [ ] 3.8. Админ-панель: перевод статуса заказа (Новый → Подтвержден → В поездке → Завершен).
- [ ] 3.9. Форма обратной связи: успешная запись сообщений пользователей в БД.
- [ ] 3.10. Кастомная страница 404 при переходе по некорректным URL-адресам.

## 4. Чек-лист форм и валидации
- [ ] 4.1. Обязательные поля помечены звездочкой `*`.
- [ ] 4.2. Блокировка отправки пустых форм (валидация на клиенте и дублирование на сервере).
- [ ] 4.3. Проверка формата e-mail по регулярному выражению.
- [ ] 4.4. Проверка маски номера телефона (`+7 (XXX) XXX-XX-XX`).
- [ ] 4.5. Проверка формата водительского удостоверения (10 цифр).
- [ ] 4.6. Понятные сообщения об ошибках выводятся непосредственно под соответствующими полями.
- [ ] 4.7. Предотвращение дублирования заявок при многократном нажатии на кнопку отправки.

---

## 5. Чек-лист безопасности
- [ ] 5.1. Пароли пользователей сохраняются в базе данных исключительно в виде bcrypt-хеша.
- [ ] 5.2. Проверка SQL-инъекций: инъекции вида `' OR '1'='1` в строке поиска и форме авторизации экранируются параметризованными запросами.
- [ ] 5.3. Защита от XSS: теги `<script>alert(1)</script>` в отзывах и сообщениях обезвреживаются.
- [ ] 5.4. Закрытый доступ к страницам `/admin/*` без авторизации с ролью администратора.
- [ ] 5.5. Невозможность просмотра чужой истории поездок путем подмены ID заказа в URL.
- [ ] 5.6. Наличие CSRF-токенов в формах изменения данных.
